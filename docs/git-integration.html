Integración con git

Autor, fecha, y por qué se precalcula todo

Ariadne muestra tres cosas basadas en el historial de git, todas construidas sobre el mismo dato base: autor y fecha del último commit por archivo, y un historial corto (últimos 5 commits) para "ver historial".

Por qué usa git log por línea de comandos en vez de git2

src/extractor/git_blame.rs corre el binario git como subproceso en vez de usar la crate git2 (bindings de libgit2). La razón es pragmática: Ariadne ya asume que el proyecto que analiza tiene git instalado y en PATH, así que correrlo como subproceso significa cero dependencias nuevas, cero tiempo de compilación de una librería en C, y funciona igual en cualquier plataforma donde git ya esté disponible. Es consistente con el resto del extractor: heurística simple y con límites conocidos, no necesariamente la solución más elegante posible.

Un solo git log, no uno por archivo

collect_commit_history_by_path corre un git log --name-only sobre todo el historial del repo y arma un mapa de ruta a los últimos N commits, caminando de más nuevo a más viejo y registrando cada ruta hasta completar N entradas. La alternativa obvia, un git log -- <archivo> por cada archivo del proyecto, escala mal: cientos de archivos significarían cientos de procesos de git.

Por qué el HTML no puede pedir nada en vivo

El HTML generado es un archivo autocontenido sin servidor. Cuando alguien lo abre, no hay ningún proceso de Ariadne corriendo para responder "dame el historial de este archivo". Por eso "ver historial" muestra como máximo 5 commits precalculados al generar, en vez de un git log bajo demanda.

Colorear por antigüedad: por qué tono en HSL, no un canal aparte

La primera versión usaba opacidad para codificar antigüedad, pero competía visualmente con la opacidad que ya usa el "focus" de un nodo: dos significados distintos peleando por el mismo canal. La versión actual ajusta la luminosidad del color de categoría que el nodo ya tiene (más claro es más viejo), calculado en HSL a partir del hex existente. Así generaliza a cualquier paleta configurada sin hardcodear una rampa de colores por tema.

Limitaciones conocidas

  • No sigue renombres de archivo, así que un archivo renombrado pierde su historial previo en el mapa.
  • No hay blame línea por línea real. Para eso, es mejor abrir el archivo directamente.
  • Si la carpeta analizada no es un repo git, o no hay git en PATH, todo esto queda simplemente vacío sin fallar el resto de la generación.
