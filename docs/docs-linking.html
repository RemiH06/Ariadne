Vincular documentación

Cómo funciona [[docs.pages]]

Prueba viviente

Estás leyendo la prueba viviente de esta funcionalidad: esta página existe porque conf.ariadne, en la raíz del repo, tiene una entrada [[docs.pages]] que conecta el nodo src/render/docs/pages.rs (justo el archivo que la hace posible) con esta URL. Si llegaste aquí desde el panel "Nodo seleccionado" del diagrama, ya viste la funcionalidad de punta a punta.

Por qué es un link y no contenido embebido

La primera versión de esta funcionalidad convertía Markdown a HTML y lo embebía dentro del propio diagrama, en una sección "Documentación" aparte. Se simplificó a propósito. El diagrama sirve para navegar la documentación, no para mostrarla, y una página de documentación real (con sus propias animaciones, su propio diseño, su propio lugar en un sitio) funciona mejor viviendo aparte que encajada dentro del HTML de otra cosa. Ariadne ya no lee ni convierte nada: solo valida que el nodo exista y le pasa la URL al cliente.

Por qué es un mapeo explícito y no un auto-descubrimiento

La alternativa obvia sería una convención del tipo "si existe docs/<mismo-nombre>.html, conéctalo solo", pero eso falla en cuanto un proyecto real no sigue esa convención. La mayoría no la sigue: la documentación vive en cualquier estructura, con cualquier nombre, a veces ni siquiera cerca del código que documenta, y a veces ni siquiera en el mismo repositorio (puede estar en el GitHub Pages de otro proyecto).

Nunca falla en silencio

Un mapeo explícito en conf.ariadne es más largo de escribir, pero o el nodo existe, o ariadne generate falla con un error claro que señala cuál entrada está mal.

Cómo se arma

[[docs.pages]]
node = "src/render/docs/pages.rs"   # debe coincidir con el id de un nodo del grafo
url  = "docs-linking.html"          # relativa, o una URL absoluta

Al generar (src/cli/generate.rs) pasan tres cosas:

build_doc_pages · src/render/docs/pages.rs

Resuelve cada entrada contra el grafo ya construido. Solo valida que el node exista, nada más.

metadata.doc_url

El nodo correspondiente gana este campo, que el cliente usa para dibujar la estrella y como href del link "Ir a documentación".

nada se embebe

El link simplemente lleva a donde pusiste el contenido, como cualquier link normal.

Por qué solo archivos y no carpetas

Una carpeta podría en teoría tener una página de resumen del módulo, pero documentar una carpeta y documentar todo lo que se tocó dentro de ella son cosas distintas, y mezclarlas hubiera complicado el diseño sin un caso de uso concreto que lo pidiera. El node de [[docs.pages]] podría apuntar a un id de carpeta sin cambios grandes si esa necesidad aparece, pero no se construyó de forma especulativa.
