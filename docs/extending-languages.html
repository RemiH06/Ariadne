Agregar un lenguaje nuevo

El patrón compartido entre extractores

Ariadne soporta hoy 15 lenguajes para dos cosas distintas, referencias entre archivos (src/extractor/imports.rs) y clases, métodos y atributos (src/extractor/classes.rs), con el mismo patrón en ambos módulos:

  1. Un dispatcher público (extract_imports/extract_classes) que hace match language { "python" => ..., "rust" => ..., ... }.
  2. Una función de extracción por lenguaje.
  3. Scanners de bajo nivel compartidos entre lenguajes para no repetir la parte difícil (encontrar dónde termina un bloque) en cada uno.

Los dos estilos de "dónde termina un bloque"

  • Por indentación (Python, Ruby, Elixir, Julia, Haskell): el cuerpo son las líneas siguientes con más indentación que la línea de cabecera, hasta la primera línea con indentación igual o menor. Función: indented_body_end.
  • Por llaves (JS/TS, Rust, Go, Java, Kotlin, PHP, C/C++): balancea { } ingenuamente. Función: braced_body_end. Necesita las líneas ya enmascaradas, porque un solo string o comentario con una llave suelta desincroniza el conteo para el resto del archivo.

mask_source/mask_line: por qué existe

Un contador ingenuo de { } o ( ) se rompe apenas hay un string, un comentario, o (en JS/TS) un literal de regex con esos caracteres adentro. mask_source reemplaza todo eso por espacios antes de contar, línea por línea pero con estado de bloque de comentario cruzando líneas. Esto se descubrió de la forma difícil: un comentario de varias líneas en client/src/render.ts desincronizaba el conteo de una clase a partir de cierto punto del archivo, y por separado un literal de regex también desbalanceaba paréntesis sin ser un comentario. Las dos causas ya están cubiertas, pero es la clase de bug que este enmascarado previene en general.

Cómo agregar un lenguaje

  1. Imports (imports.rs): un brazo al match de extract_imports con una función heurística de línea. Si el lenguaje tiene imports relativos a archivo, también un brazo en resolve_relative_import. Si tiene convención de paquete propio, una función resolve_<lang>_absolute nueva.
  2. Clases (classes.rs): un brazo a extract_classes, con una función que reusa indented_body_end o braced_body_end más top_level_lines según el estilo del lenguaje.
  3. Tests: cada lenguaje tiene entre 1 y 3 tests unitarios en el mismo archivo. Cubre al menos nombre de clase, un método, un atributo, y algún caso borde específico del lenguaje si lo hay.

Salvedades honestas ya conocidas

  • Julia: no tiene métodos por diseño, porque usa multiple dispatch y no existe el concepto de "método de una clase".
  • R: el más frágil, porque conviven dos sistemas de OOP distintos (S4 y R6) con parseo de list() anidado a mano.
  • Workspaces y monorepos (Rust/Go/PHP): la resolución busca el manifiesto ancestro más cercano al archivo, descubierto escaneando el árbol. No lee [workspace].members de Cargo.toml ni nada equivalente.
